# 不足機能の論点

機能の利用目的で分解します。計算結果への引用と文献への引用には共通部分がありますが、今回のMVPはrun/file versionへの引用に限定します。

```text
Q0 要件決定者は何をMVPに補い、何を後続へ残すか
Q1 研究内容を読む
  Q1.1 Markdownと数式を安全に表示できるか
Q2 計算結果の根拠をたどる
  Q2.1 引用から固定された計算・生成物へ移動できるか
  Q2.2 計算根拠の不足をローカルで報告できるか
Q3 文献・知識を蓄積して検索する
  Q3.1 文書・抽出知識・用語・矛盾を管理できるか
  Q3.2 Graph RAG、複数知識ベース、graph表示を使えるか
Q4 研究支援を拡張する
  Q4.1 Skills/MCPを承認・版管理してprojectに割り当てられるか
  Q4.2 査読支援、追加viewer、科学DB連携を使えるか
```

## 網羅性の限界

参照先の多数のSkill本文をすべて監査したわけではありません。共通の登録・割当・更新経路と代表的な研究支援経路を確認しました。既存の実行状態、容量、混在Notebook、診断の条件は維持し、新しい能力と重複するREQを作らないよう整理しました。

Entra ID、多人数、他LLM providerなどの元の後続機能は今回の追加判断を妨げません。参照先の実装方式を採用する判断も対象外です。
