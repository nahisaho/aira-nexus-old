## Design

One bounded renderer serves workspace chat, Notebook Markdown and Markdown file previews. Chat rendering stays always enabled; Markdown file tabs default to rendered display with a per-file source/rendered choice, and ordinary ipynb Markdown cells add independent source/rendered/edit modes under REQ-MARKDOWN-001. The dedicated journal uses direct schema-based rich editing under REQ-MARKDOWN-004/005, with source-backed scientific preview nodes using the existing bounded renderer; trusted editor-generated heading/mark DOM is not permission to insert raw Markdown HTML. The ELN's localized labels follow REQ-LAYOUT-002. There is no global scientific switch or checkbox. Non-Markdown files, code cells and original stored bytes keep their existing display semantics; the display setting does not rewrite numeric values into exponential notation. Raw HTML and Notebook rich HTML outputs never enter the active DOM. Raw HTML/SVG content is never embedded; the separate owned-image route rasterizes static SVG for both Markdown embeds and SVG file tabs.
The workspace shows escaped source while rendering is pending or unavailable and reports errors explicitly. Original source remains in records and existing editors/APIs/downloads. Markdown file buttons are 原文を表示 / レンダリングを表示 in Japanese and Show source / Show rendered in English, with mutually exclusive `aria-pressed` states. Their initial choice is rendered, applies only to .md/.markdown text previews and remains local to each open file tab; reopening a closed tab or reloading resets to rendered display. Source mode uses the existing escaped preformatted fallback without changing sharing offsets or stored text. The low-level ScientificText renderer fixture remains separate from this workspace control.
Valid YAML front matter is excluded from formatted Markdown, not from stored/raw source, downloads or exports. Workspace-authored YAML dates and self-declared editor history follow REQ-MARKDOWN-002; TEST-RENDER-005 verifies that metadata remains in raw source while the body and math render normally.
Math conversion uses a terminable worker (64 MiB old/16 MiB young heap, no inherited execArgv), then allowlisted Markdown/MathML sanitization with trust=false. Limits: 8 KiB/formula,100 formulas/view,1000 expansions,1 MiB output and1 second/task; enforce actual message bytes and escaped visible errors/source, not only metadata. Slice64 KiB UTF-8 only on scalar boundaries; no raw rich HTML/SVG, automatic citation resolution or remote media.
Owned image references are the explicit local auto-load exception: the Markdown worker validates both UUIDs and emits `/api/projects/PROJECT_UUID/files/FILE_UUID/image`, never a user-supplied URL. The endpoint independently enforces ownership/project scope and the data preview budgets. Images use escaped alternative text, lazy loading, asynchronous decoding and responsive bounded sizing; display failure is visible. This does not resolve citations, send research to an SDK or permit external media.
Here a view is one bounded ScientificView Markdown input, not a promise of an aggregate browser/OS memory cap. `TEST-RENDER-004` owns the four/+1-image boundary and explicit omission; existing per-image pixel limits and server admission remain independent.
Mermaid12.3.0 is loaded only for Mermaid fences. Render at most 10 diagrams/view, at most 8 KiB UTF-8 source/diagram and at most 1 MiB generated SVG/diagram; configure a 100-edge flowchart limit. Reject initialization directives, frontmatter, click directives, URLs/protocol-relative references, `url(...)`, HTML tags and image/icon `@{...}` syntax before rendering. Lock strict security, disabled HTML labels, Dagre layout and the sensitive configuration keys. Use a temporary hidden measurement container, remove it after rendering, do not bind generated interactions, and display only a decoded Blob-backed image in scientific content. Release temporary nodes and Blob URLs on cleanup; keep source/error fallback when rendering is refused or fails.
`TEST-LAYOUT-007` owns exact/+1 diagram count, input/output byte and edge limits, directive rejection, no foreign requests during the measurement phase, and temporary-node/Blob cleanup on success/failure/cancel. No temporary live markup is retained after completion; the final diagram uses a fresh Blob of generated SVG, not an adopted live SVG node. These are required new assertions, not claims about the existing test body. TEST-RENDER-005 belongs to REQ-MARKDOWN-002 and verifies metadata exclusion; cross-feature TEST IDs resolve to their annotated test files rather than duplicate definitions in these specs.

## Assumptions / risks

Pinned spike packages markdown-it15.0.3/KaTeX0.19.1/sanitize-html2.18.1 establish prior art, not automatic dependency permission or parser/viewer qualification. Budgets await human approval; worker heaps are not OS isolation. MathML does not establish correctness; existing ownership/raster limits remain.

Actual worker messages at 1 MiB and 1 MiB+1 verified the outer output guard; expanded formulas may hit timeout before the inner output cap, not prove arbitrary math completion. Evidence: session files/scientific-consent-spike/attempt-2821f11c-0541-484c-ab7e-65b7eabef005/validation.json. Existing renderer tests retain responsibility for limits/sanitization. This documentation synchronization does not renew historical evidence or approvals.
