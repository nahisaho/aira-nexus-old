## Design

Compose a responsive CSS-grid shell using Tailwind CSS, shadcn/ui primitives and Lucide icons with the existing localized semantic dialogs/tabs/menus. Reuse viewer/editor and confirmation logic. Project-keyed state contains the fixed AI Chat/Lab Note pair followed by a discriminated sequence of ipynb-ID and file-version-ID viewers. The fixed Lab Note resolves the server-owned association under REQ-NOTE-004, never the first ordinary notebook. Keep its editor and all dynamic editors mounted across ordinary tab switches, track dirty/busy state separately, and guard project departure against every dirty editor rather than just the selected one. Pointer drops and keyboard moves operate only on the dynamic sequence. Missing/failed Lab Note loads keep the fixed tab visible with an explicit error, never a success-shaped empty editor or browser-created replacement.
The workspace shell owns per-viewer dirty/busy state and project admission. Pending mutations include save, execution submission/stop, confirmed restore, accepted Notebook changes and project-wide Git retry/rebuild; Notebook create/import also blocks project departure until settled. Only the originating busy viewer's close is disabled; other viewers may switch/reorder/close under their own guards. Read-only loads may be canceled by closing. Bind every async callback to project ID, viewer identity and open generation; a late response from a closed/reopened viewer or departed project cannot select a tab, replace a draft or clear another generation's busy state. Selecting the already-open project does not reset its viewers.
The fixed journal tab is 実験ノート in Japanese and Lab Note in English through the shared dictionary. The explorer's independent notebook manager is labeled ipynb in both languages; its existing create/import actions remain available. Dynamic notebook tabs retain saved research names. Do not select or rename an existing ipynb merely because its name contains Lab Note or ELN. The dedicated journal is Markdown-only, uses the journal-level editable Text/direct rendered controls and toolbar under REQ-MARKDOWN-004/005, reuses saved history and exposes no code-execution controls. Preserve ordinary notebook routes, identities, names, authoring and saved/execution history.
In Japanese, the sidebar menu labels are 詳細を編集, ピン留め / ピン留めを解除 and アーカイブ; group headings are ピン止め済み and 最近のプロジェクト. Project navigation metadata is persisted in PostgreSQL under the projects contract, not browser appearance preferences. Archive confirmation binds the chosen project's ID/revision; archived research remains read-only, while pinning is still allowed.
Dirty/busy departure/archive checks belong to this client shell, which can observe browser drafts. Server archive authority remains REQ-PROJECT-005; raw API requests cannot inspect unsaved browser drafts. Pin/visit remains writer-serialized with other transactions but does not change content revision. Record a visit only after guarded project admission succeeds; canceled departure makes no visit and pinning does not discard an editor.
Creation and editing share the description control and persistence path. It uses fixed field sizing, a bounded height, vertical overflow scrolling and an explicit localized accessible name; the dialog itself may still scroll on small viewports. Starting a new creation clears prior description state without changing saved projects.
Browser-local validated theme/locale preferences default to Light/Japanese when absent; desktop panes become labeled toggles/drawers at narrow widths. Bottom-left AIRA Nexus settings hosts appearance, the self-declared editor display name under REQ-MARKDOWN-003, manual diagnostics per REQ-DIAG-003, deleted-project restoration and the inert integration catalog. Remove the center Files/Diagnostics toolbar buttons; retain the right explorer and mobile explorer toggle. Chat rendering remains always enabled; Markdown file tabs default to rendered display with source/rendered buttons under REQ-RENDER-006, ordinary ipynb cells retain independent source/rendered/edit buttons under REQ-MARKDOWN-001, and the journal follows REQ-MARKDOWN-004/005. There is no global scientific checkbox.
The shared scientific view displays local Mermaid diagrams and owned SVG/PNG/JPEG Markdown embeds within the existing content pane, without controls that can hide AI Chat. Diagram source remains available in a localized disclosure; failures remain visible. Images scale within the scientific view with bounded height. Ownership, no-external-media and inert-content limits follow REQ-RENDER-004/005 and REQ-DATA-004.
Opening an SVG from the explorer displays a PNG converted through the same bounded image route inside its ordinary file-version tab, not the refused raw `/preview` route. Unsafe SVG shows an explicit preview error without inserting raw SVG; exact original downloads remain available. TEST-LAYOUT-007 covers both successful and refused standalone SVG views as well as Markdown embeds.

## Assumptions / risks

Dynamic viewer tabs/order are page-lifetime state and reset to AI Chat on confirmed project switch/reload, while the fixed Lab Note remains available; closing a viewer never deletes research. Journal/ipynb switching retains every draft without destructive replacement. Confirm dirty close/project departure, guard archiving the dirty current project, and warn on page unload. Rejected close/archive/project confirmation retains all drafts. Explorer lists independent ipynb notebooks and immutable file versions without invented directories. Real Chromium desktop/mobile, keyboard, dirty-navigation, async-switch and existing TEST-UI regressions must verify these assumptions.

On 2026-11-11 the owner replaced the earlier AI-Chat-only fixed-tab decision: AI Chat must be immediately followed by one fixed project Lab Note, and explicitly confirmed that this is an independent record notebook, not a carrier for the multiple ipynb notebooks. Preserve individual ipynb/file viewers and the newer navigation, rendering, metadata and history. Earlier carrier counterexamples and Green receipts describe the previous contract and are not current evidence for this revision. The Archive action remains reversible retention, not permanent deletion.
