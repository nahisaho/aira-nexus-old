Goal: Japanese/English project/chat/notebook/files interface usable locally without credentials in the browser.

## Design

Responsive three-pane workspace per workspace-layout, with searchable project navigation grouped into Pinned/Recent projects, a fixed AI Chat/Lab Note pair, individually movable/closable ipynb/file-version tabs, pending proposals and run history. The fixed journal is 実験ノート in Japanese and Lab Note in English; the separate explorer manager is ipynb. Neither locale nor role assignment renames saved research. The project menu offers Edit details, Pin/Unpin and confirmed Archive, not permanent Delete project; details editing and creation share the optional description field. Keep the fixed journal and every ipynb editor/draft mounted across ordinary tab changes, with independent dirty/busy guards. Server derives chat/journal identities and owns scope, revision and one-use confirmation checks. The independent fixed journal is implemented; the subsequent rich-authoring/shortened Japanese label change is pending approval and fresh evidence.
Diagnostics is available only through the explicit action in bottom-left AIRA Nexus settings per REQ-DIAG-003, not a central button/tab; the central Files button is also removed while the explorer and mobile toggle remain available.
Scientific rendering is always enabled for chat and enabled by default for Markdown cells and .md/.markdown file previews without a scientific checkbox. File tabs offer source/rendered buttons per REQ-RENDER-006; ordinary ipynb cells offer source/rendered/edit buttons per REQ-MARKDOWN-001, while the journal offers editable Text/direct rendered modes and formatting/timestamp controls per REQ-MARKDOWN-004/005. Viewing modes do not change stored source; escaped preformatted source remains the loading/error fallback. Workspace Markdown uploads and explicit ELN saves maintain YAML dates and self-declared editor history per REQ-MARKDOWN-002/003, using the browser-local editor name in AIRA Nexus settings. Markdown supports current-project `aira-file:UUID` image embeds and inert local Mermaid diagram images per REQ-RENDER-004/005; TEST-LAYOUT-007 verifies actual SVG/PNG decoding, diagram rendering and absence of external requests/active content. PNG/JPEG and the separate static-SVG-to-PNG route follow REQ-DATA-003/004. SVG file tabs use the same validated PNG image route, while HTML files remain attachment-only and raw SVG downloads stay unchanged. Rich HTML/MIME history stays inert. No prefetch or ambient SDK expansion for citations; budget/refusal/omission and stale/imported/lost-state labels must be visible, including archived read-only views.

## Assumptions / risks

UI tests use real PostgreSQL and controlled Copilot transport, not a fake production mode; live SDK checked separately. Human chat deferred because MVP has one user.
