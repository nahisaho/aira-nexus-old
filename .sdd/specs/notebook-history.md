# ELN saved versions and automatic local Git export

Goal: retain every committed notebook edit as an inspectable version in PostgreSQL, compare and restore saved content, and automatically export committed versions to an application-owned local Git repository without executing research or publishing it.

Scope decisions confirmed by the owner on 2026-11-11: DB versions and local Git are both in scope; Git export is automatic after successful saves, never pushes externally; retain all versions without application-specific capacity limits or automatic deletion.

## Design

PostgreSQL versions and outbox records are authoritative; local Git is a derived representation.
The existing writer transaction binds edits, history and export intents, while bounded Git processing occurs after commit.

### Authority and transaction boundary

PostgreSQL is authoritative. Add an append-only version relation and separate mutable export-state/outbox relation. A version has an ordered identity, notebook/project/actor/revision, canonical content/hash and server-recorded event metadata. Grant the application only SELECT/INSERT on versions, never UPDATE/DELETE. The migration role retains schema authority; this is not protection against the OS/DB administrator.

Integrate recording into the existing notebook insertion and `saveInTransaction` paths so GUI, raw API, PATCH, import and accepted AI proposals share the transaction. Server code selects operation origin; request-supplied editor/reason are validated and self-declared, never an authenticated author or instruction. Repeated successful saves retain the existing revision-increment behavior even if source is unchanged; unchanged YAML still gains no fabricated editor entry.

Use a unique `(notebook_id, revision)` constraint. The global ordered version ID is allocated only inside `Operations.write`, whose single lease connection and promise tail serialize complete mutation transactions through COMMIT; do not allocate IDs before entering that fence or from read pools. Thus a later application commit cannot overtake an earlier allocated ID. Baselines in the same migration use deterministic notebook-ID order, not invented historical chronology.

The history migration must acquire the existing writer advisory key transactionally with try-lock and fail explicitly if an application writer is active; run schema creation/backfill in one transaction. Failure leaves no applied schema-migration receipt so a quiescent rerun can succeed. Backfill one current baseline using server time and explicitly unknown historical editor, with uniqueness/conflict protection. Earlier edits cannot be reconstructed. Do not initialize state, change the current revision, rename research or alter current execution projections. Restore validation checks exactly one matching saved version for every notebook's current revision. Ordering/cursors permit sequence gaps after rolled-back transactions.

Accepted AI changes record server-derived `proposal` origin and the accepted proposal ID; distinguish proposed-by-AI from user acceptance and do not infer a human editor from the model. Raw API writes default to a clearly self-declared local editor. Creation/import/baseline/save/restore origins remain distinguishable.

### Content and views

Retain ordered cells and source metadata, including inline notebook attachments needed to restore content. Normalize native code outputs to empty with null execution count in saved source snapshots; execution/run artifacts remain their existing immutable records and are not copied as new executions. Referenced owned files remain UUID references. Inline notebook attachments are part of notebook content and may consume storage in multiple versions; content-addressed attachment deduplication is not part of this change.

Use an integrity hash over a specified canonical saved-content representation and verify it before export/restoration. Lists exclude snapshot bodies and use validated positive integer cursors, maximum 50 records/page. Read-only detail and diff displays enforce explicit byte limits with disclosed omissions/refusals; the DB snapshot remains complete. Compare stable cell IDs, not cell positions alone; expose source, metadata/type/language/sharing and order changes. Raw historical source/metadata stays escaped and never activates HTML, SVG or code.

Keep `/history` as execution history. Add distinct saved-version endpoints under the notebook: GET `/versions?before=VERSION_ID&limit=1..50`, GET `/versions/:revision`, GET `/versions/:revision/diff?against=OTHER_REVISION`, POST `/versions/:revision/restore`, POST `/versions/git/retry`, and POST `/versions/git/rebuild`. Match fixed Git routes before numeric revision routes. Restore sends current revision and target revision after a modal confirmation; current-revision conflict checking makes repeated/concurrent old confirmations fail. Validate the target's notebook/project/actor server-side. Do not accept client-supplied historical content as the authority.

Restoration creates a new revision retaining the selected saved source, including its historical YAML. The new server event records who self-declared the restore and when; historical YAML dates are not silently forged as today's dates. The UI distinguishes the restored content's historical metadata from the new restore event. Normal later editing/saving continues the existing YAML policy. Runtime variables are not restored, and old results remain historical/stale through the existing provenance rules.

### Git as a derived local representation

Create repositories only below a private managed history directory within the configured state root, keyed by project UUID and repository-generation UUID, with a marker binding version, project, generation and current application identity. Check resolved parents, current UID, mode 0700 and no symlinks; never adopt an existing unmarked repository. A moved same-identity state root is allowed after these checks; a restored independent application identity requires a new generation. Never derive paths from notebook names or accept a user-selected repository/path/remote. Bare Git avoids a checkout and its filters. Use bounded child-process argv/stdin with a minimal environment, disabled system/global config and hooks, no shell and no remote commands.

Export source-only ipynb plus a deterministic metadata descriptor keyed by notebook UUID; metadata contains the version/hash/origin/self-declared editor and recording time, not credentials. The Git committer is a fixed application identity, not proof of the human author's identity. Preserve other notebooks' files in the tree. Fix tree entry ordering, UTF-8 serialization, commit message and author/committer timestamp to the saved event so retries with the same parent/tree are deterministic. The authoritative identity is the DB version ID and content hash, not the derived commit SHA.

Plumbing commands create blobs/trees/commits and compare-and-swap only the expected managed ref. Persist export generation, expected parent, intended version/hash and resulting commit identity. Reconcile only an exact head event/parent/tree/content match after ref-before-ack failure. If interruption occurs before ref update and HEAD is still the expected parent (or unborn as expected), retry the same deterministic commit and CAS; an unreferenced commit object is not proof of export or divergence. Because a project processes no successor until acknowledgement, a head advanced past its earliest unacknowledged event is divergence, not permission to search/adopt arbitrary history. Never reset a divergent ref.

A single bounded worker processes committed intents in order per project. It starts only after writer acquisition, performs no Git work inside the notebook transaction and does not make notebook success depend on Git availability. Automatic attempts are capped at three for the head event, with backoff and then explicit blocked state; successors in that project wait. Other projects may continue. The scoped retry action resets/retries that project's earliest failure, coalesces concurrent clicks and never creates a new research version or skips an earlier event. Missing Git is a visible export prerequisite error, not permission to install or publish automatically.

Take an exclusively created per-generation repository lock with an owned nonce before processing. Never signal a PID from its contents or delete an unknown/stale lock. Another worker/occupied lock refuses that generation; after a hard crash, an unresolved lock is explicitly blocked until the user confirms rebuilding into a new generation, preserving the old one. This manual-rebuild availability cost is intentional; automatic stale-lock recovery is not promised. Remove only the currently owned lock in finally after confirming its child has closed; if termination remains uncertain retain the lock and report blocked. Recheck writer authority before Git admission/ref update, cooperatively cancel on observed lease loss/shutdown, and fence DB acknowledgement against the current generation. CAS is the filesystem commit point; DB and Git cannot provide a single atomic physical commit. A lease-loss race after the last check may leave a valid committed-snapshot Git ref awaiting reconciliation, never permission to mark the DB export acknowledged or to write uncommitted content.

Bound every Git command to 30 seconds, stdout to 2 MiB and stderr to 64 KiB; bound stdin to 512 MiB and reject excess explicitly rather than truncate. On timeout/shutdown terminate only the owned child, escalate to SIGKILL after a bounded grace period, and await its close before releasing the owned lock. These processing budgets are not a history-retention quota. Large/unexportable content remains in DB with an explicit blocked/error state. Read-only detail/diff responses are capped at 12 MiB, with display source capped to 64 KiB per rendered view; over-budget content returns explicit refusal and remains restorable server-side. Restart recovery applies only to derived exports, never research execution or outbound requests.

Git repositories are excluded from authoritative DB-plus-blob backups; saved versions and event IDs/hashes are included. Independent restore clears derived export/generation state, verifies every saved content hash, and checks that every current notebook has exactly one version matching its actor/project/notebook/revision/name and normalized source-only document. A missing/mismatching head fails restoration validation explicitly. Rebuild into a new private repository. Commit SHAs may differ; expose generation/rebuilt provenance and retain DB event identities/hashes, never source-machine process/path authority.

For permanent divergence or an unresolved lock, an explicit project-wide rebuild confirmation creates a new generation and requeues all retained versions in order with fresh attempt counts, expected-parent state and per-generation acknowledgements. Bind it to the displayed generation, coalesce retries, preserve the old repository unchanged and do not relabel events exported until verification in the new generation. Oversize or otherwise permanently unexportable content remains blocked even after rebuilding; do not silently skip it, raise budgets or pretend full synchronization. The UI explicitly states that a notebook's Git retry/rebuild operates on that whole project's shared repository. No reset, adoption or deletion is used as recovery.

### UI integration

Add a history action inside the existing selected-notebook viewer, not a new central fixed tab. Present saved edits separately from execution history. Use the existing locale dictionary, current revision guards, busy/dirty state and project scope. Disable restore while dirty rather than silently discarding drafts; archived users may read versions and retry derived export but cannot restore content. Show current DB-save and Git-export outcomes separately. No background fetch of external images or remote Git resources.

The 2026-11-11 project Lab Note replacement under REQ-NOTE-004/005/006 and REQ-LAYOUT-002 adds one independent Markdown journal per project, not a fixed history tab or an ipynb-manager carrier. Its editor reuses these same versions/diff/restore and project-wide local Git controls. The journal's automatic empty initialization records a real `create` event at server time with no invented human editor; later explicit saves retain the existing YAML policy. Journal restore must pass both shared Markdown-only validation and the DB type guard for current/saved journal documents. Existing ipynb versions, event IDs and exports are not rewritten; the new journal shares its project's ordered export queue. New project creation must not break Git ordering, backups, exact current-head validation or history tests by silently omitting this additional saved notebook.

Journal backup/restore follows REQ-NOTE-006: include and validate the immutable association, exactly one journal per project, Markdown-only current/history and matching head. Suppress only the journal creation trigger during data-only loading in the independent destination, re-enable before validation, and do not synthesize replacement journal IDs or relax foreign-key checks. Keep the current schema-hash refusal for incompatible archives; a pre-journal archive is not silently migrated by the restore tool.
